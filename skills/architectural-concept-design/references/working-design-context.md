# Working design context and continuous D1 revisions

Use for ongoing ordinary design, not as a gate for case studies, fieldwork,
formal state or the human-authored teaching chain. The model designs, tools
check their stated invariants, and the student controls goals and hard conditions.

## First useful design

Reuse supplied material. With reliable bounds, units and program, create actual
spatial organization and a dimensioned draft without asking for room coordinates.
Without reliable dimensions, deliver relationships and identify the missing
input rather than inventing a measured plan. Ask at most three consequential
questions together and continue independent work.

The checked slice is a single-storey small public new-build with rectangular
functional blocks and explicit traffic reservations. Respond to site access and
quiet/public relations without inventing setbacks or treating a layout container
as approved buildable land. Other conceptual tasks keep their existing routes.
Choose alternatives when useful; vary organization, entry or circulation, not
just labels. Explain proportions and unassigned space; fit is not design quality.

## One geometry, recognizable outputs

Keep an existing adequate geometry authority. For an ordinary rectangular SVG,
the actual editable block rectangles can be that authority; follow
[concept-layout-checks.md](concept-layout-checks.md). Derive tables and explanations
from those same rectangles. Do not maintain independent coordinates in Markdown.
If another source already drives the SVG, verify that projection rather than
silently changing authorities.

Deliver SVG, target versus actual areas, traffic and unassigned area, entry/
organization account, content identity and actual check scope. Include names,
dimensions, units, orientation and legend. Inspect clipping and label collisions
separately. Use the existing SVG pipeline for requested compiled/preview/renderer
evidence; a working editable SVG is not a presentation or cross-renderer PASS.

## Small project record

Reuse an equivalent record or adapt
[design-context.template.md](../assets/design-context.template.md) as project-local
`DESIGN-CONTEXT.md` when preserving work across turns matters. Do not make the
student fill it or generate empty records for unrelated requests. Keep:

- Current object, depth, valid version and AI proposal versus actual adoption.
- Supplied facts/hard conditions, separately labeled assumptions and unknowns.
- Actual partial adoption and attribute locks bound to source versions.
- One geometry authority and relative artifact paths with SHA-256 identities.
- Source-bound checks, recent changes, a useful rollback index and pending choices.

Keep targets distinct from geometric areas, functional allocation from gross
building area, and real traffic geometry from grossing factors. Copy no full chat.
Formal state retains its existing evidence, Decision and staleness tools.

## Revise and recover

1. Read current records, relevant confirmed preferences and actual artifacts.
   Recompute their identities. Missing, externally edited or mixed versions need
   a concrete user choice before claiming continuity. Current instructions win.
2. Bind partial adoption to actual versions and named attributes. “Entry from A,
   reading organization from B” adopts those parts only; coordinate the rest,
   recheck conflicts and leave unselected parts pending. Do not select both wholes.
3. Resolve consequential ambiguity in “foyer unchanged”: position, outline or
   area. Preserve the agreed attributes, not its name alone. A location lock
   does not automatically freeze dimensions or every neighboring space.
   Record the source and scope of each actual lock separately from adopted spatial
   relationships. Previous dimensions that merely stayed the same are observations,
   not additional locks or pass conditions; do not turn AI-created geometry into
   a human requirement. Unlocked blocks may change when the adopted relationships
   and all explicit conditions still hold.
4. Save a new candidate without overwriting the last valid set. Run supported
   checks and compare locks against the identified previous source. Recompute
   affected tables, figures and explanation together.
5. Promote a passing candidate only for the stated conditions, then update record
   bindings. Failure preserves the previous valid set and explains the conflict.
   The first failed attempt has no valid version yet.

For a combination or revision, compare the affected rooms' dimensions and
proportions with the actual prior drafts and identify new narrow spaces, fragmented
residual areas and circulation trade-offs. Explain material deterioration even if
areas and geometric checks pass; consider an alternative within the real locks and
relationships where practical. Do not claim a better or impossible solution
without checking it. These are design-review prompts, not regulatory limits or a
substitute for architectural review.

Default to at most three failed automatic corrections per request; stop after
two consecutive attempts with no observable improvement. Record actual failures
and changes. A later user budget is possible but must be recorded. This is not
a limit on creative alternatives or a host sandbox. Bounded failure is not proof
of global infeasibility. Do not relax facts, delete functions or silently unlock.

Restoring a prior valid version restores its geometry, derived files and record
bindings together. Old checks never attach to new SVG bytes. Retain unaffected
research. Before writing a record, reread its current bytes; reconcile concurrent
changes and preserve manual text rather than clobbering an old snapshot. Keep
only needed project-local recovery versions, with no automatic commit/upload.

## Fresh session and external edits

Read project files rather than relying on chat memory. Read relevant preferences
through [project-preferences.md](project-preferences.md). SVG is a one-way editable
delivery; arbitrary external edits are not automatically parsed back. On a hash
mismatch preserve the edited file and ask whether to use explicit new dimensions,
restore a known version or inspect the changed source. Do not regenerate over it
merely to make hashes pass, or claim an unimplemented import succeeded.

These are AI-authored working proposals. Adoption does not make them human-
authored. Do not fabricate teaching confirmations or loosen their validators.
Geometry proves no wall/door, accessibility, fire, structure, cost or construction
approval. Actual records stay private to the project, outside the installed
Skill, release/public export and any cross-project profile.
